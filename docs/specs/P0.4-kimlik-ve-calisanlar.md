password, full_name, role_id?, department_id?, position_id?, phone? } })`.
Şifre sıfırlama: `invoke('reset-user-password', { body: { user_id, new_password } })`.

Kullanıcının kendi şifresini e-posta ile sıfırlaması: `supabase.auth.resetPasswordForEmail`
(service_role gerekmez, frontend'de).

## GÜNCELLEME — Kayıt akışı yeniden tasarlandı (uçtan uca test sonrası)

İlk tasarım, `handle_new_user`'ın `app_metadata`'dan `created_by_admin`/`role_id`
okumasına dayanıyordu. Uçtan uca test bunun ÇALIŞMADIĞINI ortaya çıkardı: GoTrue
`admin.createUser`'ın `app_metadata`'sı AFTER INSERT trigger'ına insert anında
görünmüyor (bkz. [gotrue-app-metadata-zamanlamasi.md](gotrue-app-metadata-zamanlamasi.md)).
Yeni tasarım (migration `20260725160000`):

- **Birincil kayıt kilidi PLATFORM'da:** Supabase "Allow new users to sign up" KAPALI
  (elle; bkz. [supabase-panel-ayarlari.md](supabase-panel-ayarlari.md)). Self-signup
  imkânsız; kullanıcı yalnızca admin API ile oluşur.
- **`handle_new_user` sadeleşti:** minimal köprü satırı (id, email, full_name,
  role_id=null, must_change_password). İlk kullanıcı (count=0) → owner. Yedek kilit
  `user_metadata.created_by_admin` (app_metadata güvenilmez; forge edilse bile role_id
  metadata'dan gelmediği için zararsız).
- **`create-user` iki adımlı (fail-closed):** `admin.createUser` → insert sonrası
  service_role UPDATE (role_id, department_id, position_id, phone, created_by,
  must_change_password). UPDATE başarısız → kullanıcı ban'lanır (rolsüz/yarım kalmaz).
- **`bootstrap-owner` (yeni, verify_jwt=false):** ilk owner'ı kurar. X-Bootstrap-Secret
  (Supabase secrets: BOOTSTRAP_SECRET) + `public.users` boş olmalı → tek kullanımlık.

### Uçtan uca doğrulama (`scripts/e2e_api.mjs`, 12 PASS)
